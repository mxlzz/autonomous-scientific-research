## 3. Derechos, recursos, seguridad y medición — gates P0

- **Licencias por capa:** harness MIT, dataset [Hugging Face](https://huggingface.co/datasets/siegelz/core-bench) etiquetado MIT, *capsule original y datos* con derechos individuales no inspeccionados; ExPSO GitHub [GPL-3.0](https://github.com/insafkraidia/ExPSO/blob/269455e595e14ba1af5ccc0439271037e4da2ccd/LICENSE) sólo acredita ese software. **No redistribuir tar, datos, outputs o raw prompts** ni tratarlos como MIT globalmente.
- **Disponibilidad/volumen:** el proyecto hospeda archivos bajo `corebench.cs.princeton.edu`. Se intentaron accesos documentales de las URLs `capsule-5975162.tar.gz`, `capsule-7935517.tar.gz`; la búsqueda/navegador no pudo abrir archivos tar y un intento HEAD desde entorno de trabajo devolvió `curl: (6) Could not resolve host`. **No hay `Content-Length`, respuesta HTTP verificada, hash de tar ni lista de ficheros**. El tamaño es **desconocido**. No confundir carencia de acceso aquí con URL inexistente.
- **Requisitos:** `train` declara Python/R, sin CPU/GPU por registro; el detector original inspecciona `REPRODUCING.md` sólo *después* de descargar. Un script de optimización Python puede necesitar GPU o tardar mucho; no asumir CPU-only, ni que el filtro `--no_gpu` es validación de hardware. **No existe tiempo/RAM/costo observado para A o B.** La publicación CORE seleccionó cápsulas para reproducirse en un entorno concreto; no implica caber en el runner gratis en 15 minutos.
- **Seguridad:** `tar.extractall` puede tener rutas/symlinks peligrosos; `privileged=True` concede exceso de acceso al contenedor. Protocolo futuro: comprobar hash/tamaño, inspeccionar encabezados tar de forma *estática*, rechazar nombres fuera de raíz, enlaces y tamaño descomprimido excesivo; revisar licencias `LICENSE`/metadata/Dockerfile/`REPRODUCING.md` sin ejecutar; solo después usar VM efímera aislada sin secrets, red controlada, límites CPU/RAM/tiempo y **sin Docker privilegiado** si la tarea lo permite. Si no puede aislarse, **no ejecutar**.
- **Independencia del scorer:** `core_train.json` contiene **`results` con gold junto al prompt**. Un agente jamás debe recibir el JSON completo ni acceso al directorio del evaluador; construir una proyección solo `task_prompt` + nombres de preguntas y auditar que los resultados no se filtren por `environment/results`, logs, o `correct_result_paths.txt`. Scorer original sólo tras corte, en proceso/FS separado. `score_results` contempla respuestas numéricas con intervalos que pueden ser degenerados si tres runs tienen varianza nula; revisar con tests sintéticos independientes, sin cambiar tolerancias originales.
- **Trazas:** el repo público y artifacts de Actions NO son almacén confidencial; requiere política T0.7 de manifest allowlist + custodias/reproducción autorizadas. Una run cancelada puede destruir métricas, como en T0.13. Exigir telemetría incremental y watchdog con recuperación/flush antes de permitir benchmark, más método de valoración de costo integral.
