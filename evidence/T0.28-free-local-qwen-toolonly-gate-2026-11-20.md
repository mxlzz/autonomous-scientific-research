El modelo debe comportarse como un **backend OpenAI Chat Completions con herramientas** para fuente fijada [`Btwestyo/sciresearch-eval@9d391b3aa8daf8d0b944acda12c7f8b089a1d8e0`](https://github.com/Btwestyo/sciresearch-eval/tree/9d391b3aa8daf8d0b944acda12c7f8b089a1d8e0). Fuente original [`src/sciresearch_eval/agents/openai_backend.py`](https://github.com/Btwestyo/sciresearch-eval/blob/9d391b3aa8daf8d0b944acda12c7f8b089a1d8e0/src/sciresearch_eval/agents/openai_backend.py) Git blob `62226f9e814af28593763281ed8cf5e25dc6cc5d`: `OpenAICompatAgent.converse()` envía a `{base_url}/chat/completions` el body `model,messages,tools,tool_choice,max_tokens`. El traductor convierte `choices[0].message.tool_calls` en bloques `toolUse` y resultados de herramientas a mensajes `tool`. [`agents/harness.py`](https://github.com/Btwestyo/sciresearch-eval/blob/9d391b3aa8daf8d0b944acda12c7f8b089a1d8e0/src/sciresearch_eval/agents/harness.py), Git blob `194a4b36caf4cd702caee34044ec457247644aee`, acepta `selfhost:<nombre_servido>` con `base_url`; endpoint de Ollama previsto `http://ollama:11434/v1` en red interna Docker. `AgentTools` describe herramientas particulares de la condición; el guard validado sobre copia del harness en [T0.25](T0.25-sciresearch-original-harness-dispatch-2026-11-20.md) es **obligatorio para cualquier actor real**, porque upstream sigue aceptando nombres no anunciados.

**Incompatibilidad documental MATERIAL:** [compatibilidad OpenAI oficial de Ollama](https://docs.ollama.com/api/openai-compatibility) incluye `/v1/chat/completions` y `tools`, pero declara `tool_choice` **no soportado**. El adaptador original **siempre** incluye `tool_choice="auto"` o una función `submit` forzada. **No se verificó si Ollama rechaza (HTTP400), ignora u opera parcialmente** con este campo; tampoco que específicamente Qwen3 0.6B produzca tool calls correctas. El [manual oficial de tool calling de Ollama](https://docs.ollama.com/capabilities/tool-calling) documenta la característica general, no rendimiento de 0.6B. Por tanto **NO-GO para invocar directamente el cliente original sin comprobar/corregir esa incompatibilidad**.

**Adaptación mínima que se debe medir T0.29:** en una **copia documentada** del adaptador OpenAICompatible, **omitir `tool_choice` únicamente para Ollama** y no fingir `submit` forzada si el backend no la garantiza. El harness puede anunciar solo `submit` durante fase final y verificar rigurosamente todos los `toolUse` con el guard de [T0.25](T0.25-sciresearch-original-harness-dispatch-2026-11-20.md). Limitar explícitamente `MAX_TURNS` (upstream 80), `MAX_TOOL_CALLS` (upstream 60), `MAX_OUTPUT_TOKENS_PER_TURN` (upstream 32000) y timeout/reintentos del backend para CPU: **un límite distinto del benchmark oficial**, consignarlo y no usarlo como benchmark comparable al de autores. Conservar `ThermalEnv`, `AgentTools` y `grader.grade` científicos originales.
