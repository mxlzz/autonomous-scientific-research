**Sin dictamen legal universal:** una traza individual mezcla contenido protegido por licencias distintas y quizá secretos o datos obtenidos vía herramientas. La autorización de conservar/compartir varía por **slot, campo, destino y lector**. El análisis aquí identifica condiciones públicas, no constituye una opinión jurídica.

## 2. Modelo de amenaza y clasificación de campos

| Campo de evidencia | Público en repo y Actions | Control requerido |
|---|---|---|
| Repositorios, SHA, código de workflow, package lock/versiones, licencia, dataset **ID/revisión pública**, split, seed, límites CPU/RAM, timestamps, presupuesto, hashes | **Sí**, sin tokens en URL, nombre de fichero o registro | manifiesto inmutable; evitar IDs si son sensibles/no redistribuibles en términos |
| Métricas agregadas no invertibles: resultado del scorer C/I, tiempo, totales tokens/llamadas, costos, tipo de error genérico, hashes | **Condicionalmente sí**, previo examen de términos/PII y tamaño de agrupación; ID+score sobre una muestra puede revelar benchmark privado si hay claves filtradas | revisar si un score/índice constituye dato restringido o información personal; para privado, agregar u omitir |
| Prompt, instrucciones/ejemplos del dataset, `target`, código de referencia, rúbricas ocultas, soluciones de evaluación, eventos completos Inspect JSON | **No por defecto**, especialmente AstaBench gated | preservar sólo tras clasificar por licencia y destino; no stdout, cache ni artifacts públicos; auditor con permisos propios |
| Outputs y código del modelo, tool traces, archivos experimentales | **No automáticamente**: pueden reproducir entradas o datos del dataset, secretos, contenido de terceros | inspección de contenido, atribución, sanitización conservadora; si no es legal conservar, manifest+rehidratación, reportar limitación |
| API tokens, credenciales, cookies, variables secretas, rutas privadas | **Nunca** al repo/log/artifact | inyección por secrets mínimos, no serializar; bloqueo de publicación ante detección |

Riesgos añadidos: (i) `set -x`, `tail` de errores o exception traceback pueden reflejar prompts; (ii) `actions/cache` no es almacén seguro ni rastro durable de auditoría; (iii) base64 o cifrar y subir a repo público **no transforma automáticamente la redistribución en uso permitido**; (iv) hashes sin el artefacto rehidratable no permiten inspeccionar razonamiento retrospectivamente; (v) campos aparentemente anónimos combinados con benchmark restringido pueden revelar datos.

## 3. Comparación de soluciones existentes y decisión de ingeniería

| Alternativa | Ventaja | Limitación real | Decisión |
|---|---|---|---|
| **A. Solo repo GitHub público + Actions artifacts** | ya operativo y gratis para runners estándar públicos | descarga por terceros; vencimiento; incompatibilidad con datos gated/secretos | **Descartar** para contenido bruto restringido; mantener **solo manifiestos sanitizados** |
| **B. Repositorio GitHub privado distinto, con acceso por auditor** | control de lectura, Git/LFS/Actions nativos; revisor puede inspeccionar | requiere crear/autorizar cuenta/repositorio y auditores, cuota de minutos/almacenamiento privados, todavía sujeto a licencias y cifrado de secretos; no existe uno autorizado específico para este proyecto | **Reserva**, no crear sin requerimiento ni atribuir acceso/uso gratuito |
| **C. Archivo local bajo control del usuario** | control de permisos y datos, puede ser 0 USD adicional | este agente no tiene acceso comprobado al dispositivo del usuario ni sincronización desde Actions; backup/traslado requiere trabajo y validación | **Reserva**; no prometer implementación remota |
| **D. Artifact cifrado almacenado públicamente** | compartible con decrypters autorizados | el ciphertext es una copia/derivado; permisos de redistribución por licencia sin resolver, claves/rotación/retención; almacenamiento público sigue visible | **No recomendado** sin licencia explícita y revisión de amenaza |
| **E. Manifiesto público reproducible + datos de origen rehidratables bajo licencia propia** | mínima complejidad, compatible con repositorio canónico público, sin nuevas credenciales; revisor recupera fuente en origen si tiene derecho; permite fijar commits/hash/códigos y volver a ejecutar | no preserva trayectoria original con incertidumbre estocástica; datasets gated requieren acceso individual del revisor; para resultados/iteraciones de agentes no auditables a posteriori sólo auditoría reproducida | **Preferida por defecto para fuentes públicas y desarrollo**; suficiencia de evidencia depende de que tarea, entradas y outputs permitan auditoría efectiva |
| **F. Manifiesto público + traza privada en repositorio/almacén autorizado (B o C)** | revisión **exacta** de ejecución si las condiciones permiten conservar; cadena de custodia más completa | condicionada a almacenamiento autorizado, derechos de datos, acceso de auditor, cuotas | **Ruta complementaria para etapa con restricciones**, no activada |

**Recomendación T0.7:** adoptar **E como estándar inmediato** y F **solo cuando una tarea lo justifique y exista permiso/licencia/almacenamiento confirmado**. **Priorizar en T0.8 tareas con datos de licencia pública y evaluador determinista**, de modo que pueda guardarse la traza cuando sea legal, sin secretos y sin infraestructura nueva. Mantener GitHub como índice/estado canónico de todos los experimentos, pero no suponer que un repositorio público puede ser almacén universal de evidencias.

## 4. Contrato mínimo de trazabilidad futuro (propuesta, no prueba ejecutada)

En cada ensayo futuro **antes de ejecutarlo**:
1. Definir `dataset_id/revision`, URL fuente/autor/licencia, relación de `split` original vs derivado, `sample_id`, `task_id`, prueba holdout y permiso explícito para cada `input`, `target`, rúbrica/feedback y `output`.
2. Definir `source_commit` y dependencias lock, modelo **ID+digest**, temperatura/seed reales o `null`, sandbox/scorer code+runtime, tool permissions, recursos/límites, presupuesto y wall-time.
3. Clasificar cada campo como `public`, `authorized_private`, `recompute_only` o `never_store` y registrar **justificación/licencia**. Los metadatos no se vuelcan por defecto si pueden ser sensibles.
4. Volcar manifiesto JSON **público y validado con allowlist** de campos, hash de salida sanitizada, score y costos; el artefacto bruto sólo se guarda si `retention_authorized=true` con destino y auditores confirmados. **No imprimir logs de excepción completos** en acciones públicas.
5. Revisor independiente con acceso propio reejecuta desde revisión inmutable si es legal. Guardar hash, diferencia de scores y causas de irreproducibilidad. Si no se conservó output bruto, declarar **`trajectory_audit=unavailable`**, aunque el score sea reproducible.
6. No inferir que la ausencia de datos sensibles al revisar un resumen de logs prueba ausencia en todas las caches/artefactos. Si hay fuga, detener, controlar acceso y seguir protocolo de incidentes.
7. Costos: incluir CI minutos públicos o gasto imputado, CPU-segundos, memoria, tokens, uso GPU y esfuerzo de recuperación; `paid_api_USD=0` no equivale a `total_cost=0`.

**No hay nueva implementación ni credenciales creadas.** Los futuros validadores pueden ser un pequeño schema JSON/allowlist antes de subir manifiestos; reutilizar `jsonschema` o validación de tipos existente antes de escribir un framework.

## 5. Próximo gate y necesidad de intervención

**T0.7 se resuelve documentalmente sin intervención inmediata:** está seleccionada la arquitectura de evidencia mínima E y las condiciones para F. **Aún NO se ha demostrado conservación de traza completa ni auditoría independiente**; eso no se promete hasta escoger tarea/datos.

**Siguiente unidad T0.8:** buscar/revisar instancias de **investigación científica de extremo a extremo** con dataset público y evaluador verificable, preferentemente determinista o basado en experimentos reproducibles, que no requiera infraestructura o API paga. Si se encuentra, fijar selección y preparar protocolo legalmente auditable. Si la única opción razonable exige acceso restringido/retención privada o gastos, parar y solicitar intervención, no sustituir scorers.
