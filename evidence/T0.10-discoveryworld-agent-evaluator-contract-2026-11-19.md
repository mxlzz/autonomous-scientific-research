# T0.10 — Selección de interfaz segura agente/evaluador sobre DiscoveryWorld

**Fecha:** 2026-11-19, Argentina. **Unidad H0/T0.10.** Revisión de código fuente oficial y de la viabilidad de adaptarlo con mínima complejidad. **No se ejecutó un LLM ni se cambió upstream**; la prueba técnica previa [T0.9](T0.9-discoveryworld-cpu-preflight-2026-11-19.md) demostró CPU/headless y scorecard original.

## 1. Riesgo real observado en fuentes inmutables

Fuente común `allenai/discoveryworld@fd591323920be0d3786ef350955de1945aa571e5`, código Apache-2.0 (arte visual CuteRPG con licencia separada).
- [`DiscoveryWorldAPI.py`](https://github.com/allenai/discoveryworld/blob/fd591323920be0d3786ef350955de1945aa571e5/discoveryworld/DiscoveryWorldAPI.py): `getAgentObservation(0)` retorna `ui` y `vision`; la `ui.taskProgress` pública incluye texto de tarea y progreso visible, parte del contrato de juego. **`getTaskScorecard()` está documentado expresamente en código como “oracle knowledge, and should never be shown to an agent”** (comentario justo antes de método). `api.world` expone datos internos. `performAgentAction` valida JSON; `tick` avanza mundo. El objeto API **no debe entregarse como herramienta de ejecución Python a la política**.
- [`agents/RandomAgent.py`](https://github.com/allenai/discoveryworld/blob/fd591323920be0d3786ef350955de1945aa571e5/agents/RandomAgent.py) líneas aproximadas 105: `taskScorecard=api.getTaskScorecard()` **dentro de su bucle**, e imprime score según debug; además usa `api.ui` internamente. **No reutilizar sin modificación como proceso de agente con acceso restringido**. Su política aleatoria puede servir como *control nulo* si se separa del evaluador.
- [`agents/HypothesizerAgent.py`](https://github.com/allenai/discoveryworld/blob/fd591323920be0d3786ef350955de1945aa571e5/agents/HypothesizerAgent.py): integra API en mismo proceso, prompt multimodal y cliente OpenAI; usa GPT-4o por defecto, lectura de `openai_key.txt`, cálculo de costo basado en tarifas hardcodeadas; **no ejecutar la versión original como si fuera un baseline local gratis**. Prompt/schema y ciclo de reflexión pueden inspirar/adaptar un controlador mínimo, pero cambiar el modelo a Qwen3 0.6B supone **adaptación, no réplica exacta**.
- [`agents/recoma/discoveryworld_env_models.py`](https://github.com/allenai/discoveryworld/blob/fd591323920be0d3786ef350955de1945aa571e5/agents/recoma/discoveryworld_env_models.py): `SingletonEnvironment` mantiene un `DiscoveryWorldAPI` compartido, `output_tracking_info` **consulta scorecard durante las acciones** (y puede guardar observaciones, score y world history), `DiscoveryWorldAnswerer` consulta score final. El [controlador `react_controller.py`](https://github.com/allenai/discoveryworld/blob/fd591323920be0d3786ef350955de1945aa571e5/agents/recoma/react_controller.py) da ejemplos de JSON por acción; el [README ReCoMa](https://github.com/allenai/discoveryworld/blob/fd591323920be0d3786ef350955de1945aa571e5/agents/recoma/README.md) instala/ejecuta GPT4 y otros modelos con proveedores/API; configuración referencia `max_llm_cost=50.00` **no autorización para gastar**. La instrumentación original **sí puede ver** score; no equivale a que el modelo reciba score (flujo exacto aún por auditar), pero acopla procesos y facilita fugas o logs no permisibles.
- [`ActionHistory.py`](https://github.com/allenai/discoveryworld/blob/fd591323920be0d3786ef350955de1945aa571e5/discoveryworld/ActionHistory.py) define nombres y formatos de acciones `ROTATE_DIRECTION`, `MOVE_DIRECTION`, `READ`, `USE` etc.; se debe validar cada acción contra `api.listKnownActions(limited=False)`, con restricción más fuerte a lo permitido en el ensayo.

**Hallazgo:** es posible adoptar motor/scorer original y **adaptar únicamente el puente de interacción LLM**. No requiere inventar un framework de investigación ni nueva arquitectura multiagente.

## 2. Alternativas contrastadas

| Alternativa | Ventaja | Riesgo/costo | Decisión |
|---|---|---|---|
| Reusar `RandomAgent` original como LLM policy | simplicidad conceptual | acceso a `ui`, `api` y scorecard en cada vuelta; no es LLM | descartar *sin separación*, usar como referencia para formato de acciones |
| Reusar `HypothesizerAgent` sin cambios | reflexión y notas científicas en prompt | GPT-4o/imagen y API key, no costo cero; acopla world API y logs | no ejecutar tal cual, adaptar solo formato de prompt/observación |
| Reusar ReCoMa/ReAct íntegro | controlador y scoring ya implementados | scorecard por paso en instrumentación, dependencias/prompt/provider y presupuesto ajenos, mayor complejidad | reservar como comparador futuro una vez controladas fugas |
| **Controlador mínimo de entrada/salida textual** + DiscoveryWorld original + Ollama local | no ejecuta código propuesto por LLM; controla exactamente canales observación/acción y score; mínimo CPU/API | no es baseline publicada idéntica; requiere test previo del puente y registro de versión | **elegir para primera línea base LLM de simulador**, explícitamente adaptación local experimental |
| Contenedor/proceso aislado para agente ejecutor de código | frontera de sistema fuerte si el agente puede ejecutar Python o herramientas arbitrarias | complejidad/montajes/red/IPC; gasto CPU adicional | obligatorio **solo si** se habilita ejecución arbitraria de código, que el piloto prohíbe |

### Frontera mínima exigible (no es seguridad frente a ejecución arbitraria de código)

**Entorno/evaluador confiable:** único proceso Python con `DiscoveryWorldAPI`, `world`, `loadScenario`, `performAgentAction`, `tick` y `getTaskScorecard`. **Política modelo no ejecutable:** solo texto/JSON generado por un modelo local Ollama, sin `exec`, shell, import, herramientas de código o acceso a archivos internos; no se pasa referencia de objeto Python al LLM. La política recibe **solamente** (a) descripción de tarea visible/observación `ui` sanitizada (retirar `vision` por incompatibilidad de modelo textual y licencia de imágenes), (b) `listKnownActions` y reglas de argumentos legítimas, (c) confirmación de acción/observación siguiente; nunca score, subgoals ocultos, source de mundo o `criticalQuestions`. Scorer y notas del experimento quedan en el lado confiable.

Validación de respuesta: tamaño máximo JSON, **un solo objeto** `{"action":"...", "arg1":...,"arg2":...}`; `action` debe estar en allowlist exacta de acciones existentes; tipos y argumentos según contrato oficial. Bloquear `getTaskScorecard`, `world`, `__class__`, `eval`, `exec`, `python`, URLs/paths y todos los nombres que no sean acción válida. Nunca usar model-output como código o nombre de función Python; registrar los errores de formato como fallos de política (no de entorno). La frontera es suficiente **solo si el modelo no recibe otras herramientas**. Un modelo con ejecución de Python requeriría contenedor/proceso con filesystem y red aislados; no afirmar frontera de seguridad física por simple filtrado JSON.

**Medidas de observación y fuga:** revisar esquema de `ui` por campos conocidos y verificar que no contenga `scoreNormalized`, `maxScore`, `scoreCard`, `criticalQuestions` antes de cada prompt; verificar también **que la política solo invoque métodos de la lista permitida** por un controlador sin dispatch dinámico de métodos. T0.9 verificó ausencia de cuatro substrings en un caso; no constituye prueba de toda fuga ni de un agente malicioso.

**Orden:** `getAgentObservation()` → construir prompt sanitizado → modelo `Ollama /api/chat` sin tools → parse/validar acción → `performAgentAction` → `tick()` → nueva observación. Tras corte por `max_steps`/tiempo, **solo entonces** `getTaskScorecard` para cierre. No usar score para elegir la acción siguiente.

## 3. Propuesta de presupuesto preregistrable para smoke, NO corrida científica

- Modelo local de infraestructura ya verificada en T0.4/5: Qwen3 **0.6B** `ollama/qwen3:0.6b`, digest `7df6b6e09427a769808717c0a93cadc4ae99ed4eb8bf5ca557c90846becea435`; contenedor Ollama pinned `sha256:910d0d8107b538fb0894e63163eb195de0cc7aefcbc666dc62d3b18f71124592`. **No se ha probado aún que el modelo produzca un JSON de acción válido en DiscoveryWorld**.
- **Siguiente T0.11:** primero *test negativo* de acceso con 3 salidas sintéticas (`getTaskScorecard`, clave `__class__`, acción inexistente); test positivo con dos `ROTATE_DIRECTION` válidas, sin LLM, sin medir scores de desempeño; solo después smoke de **máximo 4 pasos de acción, máximo 6 llamadas LLM, máximo 512 tokens de salida por llamada**, `temperature=0` si Ollama lo admite, semilla fijada si existe; abortar ante >2 inválidos consecutivos, 4 minutos de inferencia+interacción, límite de workflow 15min, CPU 3-4, RAM Docker 6GiB/runner16GiB; los valores son **cortes de ingeniería**, no optimización científica. **Cualquier cambio queda en un commit y es configuración nueva, no réplica**.
- Salidas para auditoría: estandarizar `model_digest`, `source_sha`, `seed`, `steps/actions_valid/errors`, `time`, `input/output_tokens` de proveedor cuando disponibles, tipos de fallo y `scoreNormalized/completedSuccessfully` **solo luego del stop**; se publica allowlist, no prompt, acciones raw, worldstate, texto de terceros ni sprites. Una traza completa solo en almacén autorizado tras examen de derechos por campo T0.7; si no se conserva, `trajectory_audit=unavailable`.
- La tarea `Plant Nutrients Normal seed0` es **entrenamiento/desarrollo local**, seeds1–4 sin usar pero no tests ciegos públicamente. Aunque una muestra alcance `completedSuccessfully`, eso solo demuestra progreso **en un simulador**, no autonomía científica sobre datos reales. Mantener CORE-Bench como futuro caso de validez externa.

## 4. Estado/decisión

**D-0017: adoptar motor+scorer originales; adaptar el puente texto/JSON hacia modelo local con validador estrictamente no-ejecutable**, sin construir framework. **Se permite T0.11 solo como smoke de frontera y hasta 4 acciones de LLM local a costo de API cero**, después de aprobar los tres negativos de validación. No abrir H1/H2 ni atribuir validez científica. **No requiere intervención inmediata** para el smoke CPU; pago API=0 y datos protegidos no descargados. Trazas completas, auditor externo y experimentos científicos posteriores siguen condicionados. T0.10 es revisión documental, no experimento ni prueba de seguridad adversarial real.
