## Pregunta falsable y tratamiento único

¿Puede **Qwen3 0.6B**, servido localmente por Ollama, producir un `tool_calls` OpenAI válido bajo condiciones CPU muy pequeñas y luego realizar una trayectoria de juicio científico sobre **una tarea pública `dev` de SciResearch-Eval** mediante la API limitada del harness original, sin ver oráculo, sin herramientas de archivos y sin servicios pagos?

- **Modelo único:** Ollama `qwen3:0.6b`, hash manifest esperado **`7df6b6e09427a769808717c0a93cadc4ae99ed4eb8bf5ca557c90846becea435`**, archivo anunciado ~523MB, licencia fuente Qwen3 **Apache-2.0**. **Imagen Ollama fija:** `ollama/ollama@sha256:910d0d8107b538fb0894e63163eb195de0cc7aefcbc666dc62d3b18f71124592`. **Bench científico:** `Btwestyo/sciresearch-eval@9d391b3aa8daf8d0b944acda12c7f8b089a1d8e0` CC BY4.0; **dev task `task_525abee377`**, condición A, formato structured, seed0, scorer original `sciresearch_eval.grader.grade`, sin `oracle` como política ni test heldout.
- **Recursos:** runner estándar Github Actions Ubuntu24.04, job **12 minutos como máximo** y **costo API pagada0**; modelo Ollama <=**1CPU/2GiB** (PIDs96), evaluator SciResearch <=**1CPU/1GiB** (PIDs96), **suma <=2CPU/3GiB**, no GPU ni runners de pago. Preparación de pesos pública, sin credenciales de usuario, artefacto digest gate. Ciencia en red Docker `--internal`, **dos contenedores diferentes** con `--cap-drop ALL --security-opt=no-new-privileges --read-only`. Actor Ollama solo monta su carpeta de pesos; evaluador monta código fuente, `tasks/dev/private` y output **privado del proceso evaluador**. Ningún Docker socket ni secretos de usuario en contenedores.
- **Gate 1 — identidad/infra:** imagen digested, manifiesto de pesos coincide; actor sin FS del evaluador en mounts verificados por `docker inspect`, red interna y servicio accessible únicamente en ella. Si falla, parar sin inferencia.
- **Gate 2 — `tool_calls` real:** una única petición HTTP al endpoint `http://ollama:11434/v1/chat/completions` con **solo `budget_status`**, sin `tool_choice` (documentado incompatible con Ollama), `max_tokens=96`, timeout **60s**. **PASS únicamente** si retorna `choices[].message.tool_calls` como función `budget_status` con JSON de argumentos válido. Una respuesta textual o error no cuenta como herramienta válida.
- **Gate 3 — harness real (si 1–2 PASS):** usar copias fieles y verificadas por blob del `agents/harness.py` y `agents/openai_backend.py` SciResearch originales; **adaptaciones mínimas declaradas**: (a) guard de herramientas condicionales de [T0.25](../evidence/T0.25-sciresearch-original-harness-dispatch-2026-11-20.md) justo antes del dispatcher real, (b) omitir `tool_choice` para el backend Ollama, (c) límites temporales/tokens del harness para CPU: `MAX_TURNS=3` más eventual turno final, `MAX_TOOL_CALLS=4`, `MAX_OUTPUT_TOKENS_PER_TURN=192`, `MAX_NUDGES=1`, `max_input_tokens=5000`, tiempo global fase episodio <=**220s**, timeout backend por intento <=**50s** y sin reintentos. El original scorer `ThermalEnv/grade`, prompts, tarea y fuentes científicas **no cambian**. La compatibilidad resultante **NO equivale al benchmark original sin adaptaciones**.
- **Gate 4 — una trayectoria real** si pasan anteriores: registrar cantidad real de turns, tool calls/errores, tokens de entrada/salida, tiempos y stop reason, tool names sin argumentos privados. **Score solo si original `grade` devuelve submitted=true para el episodio realizado**; si modelo no concluye, OOM, timeout o formatos inválidos: `NO_SCORE`, no asignar 0 a resultado científico. No optimizar prompt, modificar semilla o probar otro modelo. El grader puede leer privados solo en evaluador; **nunca** incluir gold/private en input o FS de modelo.
- **Retención:** transcript/eval trace con potencial información privada se escribe únicamente en directorio efímero confiable sin subir a repositorio público, registrar SHA y resultados agregados/herramientas permitidas y valores originales de score (sin verdad privada); el resumen público JSON no debe contener outputs de sensor/dataset brutales ni prompts completos. Falta retención del transcript íntegro para replay externo, declarar limitación en lugar de publicarlo.
- **STOP:** fallo de cualquier gate => no ejecutar fase posterior ni reintentar con distinta RAM, modelo, formato o cuotas; documentar exactamente fase y causa observable, costo de Actions/humano desconocido, y decidir intervención concreta si el usuario tuviera que autorizar recursos. No llamar capacidad científica general a un caso exitoso. **Autoverificación** del mismo ejecutor, nunca auditoría independiente.
